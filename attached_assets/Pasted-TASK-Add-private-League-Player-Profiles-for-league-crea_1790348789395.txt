TASK: Add private League Player Profiles for league creators only.

IMPORTANT:
- Keep this task tightly scoped and low-credit.
- Do not refactor unrelated code.
- Reuse the existing TKO components, styling, colours, spacing, cards, tables, typography and dark theme.
- Inspect the existing league page, league database structure, authentication/session handling and existing stats queries before changing anything.
- Reuse existing data/functions wherever possible.
- Do not add a new UI library.
- If a chart library already exists in the project, reuse it.
- If no chart library exists, use a simple lightweight SVG/CSS chart rather than installing a dependency.
- Do not change existing tournament scoring, standings calculations, qualification rules or public league pages.
- Make only the minimum database changes required.

GOAL

Create an admin-only "Player Profile" page within each league.

The page is intended to help the league creator review players, season performance, attendance and club membership when managing things such as Champions Night wildcard places.

This page and its data MUST only be accessible by the authenticated user who originally created that league.

Other users, players and public visitors must not be able to:
- view the page
- access the profile API
- view club membership information
- edit membership information
- retrieve the private profile data by manually entering a URL/API endpoint

==================================================
1. SECURITY / ACCESS CONTROL
==================================================

Identify how the existing league creator/owner is stored.

Use the existing ownership field rather than creating a second ownership system.

For every Player Profile route/API:

1. Require an authenticated session.
2. Load the league.
3. Confirm:

authenticatedUser.id === league.creatorId / ownerId

(use the actual existing field name).

If not authenticated:
return the existing application's normal unauthorised response.

If authenticated but not the league creator:
return HTTP 403.

DO NOT rely only on hiding buttons in React.

The server/API itself must enforce this ownership check.

The client should also hide the Player Profile controls from anyone who is not the league creator.

4. CLUB MEMBERSHIP
==================================================

Add private league-specific membership information.

A player may be considered a club member for one league without this becoming a global player setting.

Only the league creator can change this.

UI:

When ticking it:
- set isClubMember = true
- if membershipConfirmedAt is empty, set it to the current date

When unticking:
- set isClubMember = false
- preserve the existing confirmation date unless there is a good technical reason not to

Display the confirmation date to the league creator.

IMPORTANT:
This membership information must NOT appear in public APIs/pages.

Use the smallest sensible schema change.

If there is already a league-player/member/junction table, add the fields there rather than creating a duplicate structure.
