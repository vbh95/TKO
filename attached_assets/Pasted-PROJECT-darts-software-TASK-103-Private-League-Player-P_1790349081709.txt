==================================================
WHAT & WHY
==================================================

Add an owner-only player profile for each league so league creators can review a player's:

- season performance
- tournament attendance
- tournament history
- match and leg statistics
- scoring statistics
- performance trends
- league-specific club membership

This information is intended to help the league creator review players and make future administrative decisions.

This task must NOT introduce wildcard recommendations, rankings or Champions Night qualification decisions.

Existing league standings, scoring, tournament results and public behaviour must remain exactly as they are.

==================================================
DONE LOOKS LIKE
==================================================

- Only the authenticated league creator can open a private player profile.

- Only the league creator can read or change league-specific membership information.

- Logged-out users receive the application's existing unauthenticated response.

- Another authenticated user receives HTTP 403.

- Security is enforced SERVER-SIDE, not just by hiding React controls.

- The league administration page provides a creator-only profile entry point.

- Public league pages expose no profile-management or membership information.

- Existing public APIs expose no private membership fields.

- Club membership is stored for this specific league only.

- Membership is not a global player property.

- The creator can toggle membership and see the date it was originally confirmed.

- Unticking membership does not erase the original confirmation date.

- Membership persists after refresh.

- The profile displays reliable league, tournament, match, leg, scoring and finishing statistics.

- Missing or unavailable statistics display `—`.

- Tournament history covers all tournaments belonging to that league in chronological order.

- Attendance history clearly shows attended and missed tournaments.

- Performance trend charts use the project's EXISTING Recharts/chart implementation.

- Historical league position is shown only if it can be reconstructed reliably without changing existing standings/ranking logic.

- Profile data is obtained through one efficient server request rather than many per-statistic requests.

- Existing standings and tournament results are unchanged after implementation.
