PROJECT: darts-software

TASK #104 — League Playoffs Management Page

IMPORTANT WORKING RULES

This task is for the existing `darts-software` project.

The site is currently working.

Make this change conservatively and additively.

DO NOT:
- change tournament scoring
- change visit submission
- change leg completion
- change match completion
- change standings calculations
- change ranking/tie-break rules
- change league points
- change qualification logic
- change public league behaviour
- change Charity Mode
- change OBS overlays
- refactor unrelated code
- redesign unrelated pages
- install unnecessary packages

Reuse the private player-profile/statistics work already implemented in Task #103.

Do not change how any existing statistic is calculated.

Prefer the smallest safe change.

==================================================
GOAL
==================================================

Add a private league-owner-only "Playoffs" page to help the league creator review, filter, sort and manually select players who may compete for the remaining Champions Night / promotion places.

This is an administrative selection workspace only.

The software must NOT automatically decide who should qualify.

==================================================
ENTRY POINT
==================================================

On the existing league detail/admin page:

When the authenticated user is the league creator, add a new button:

PLAYOFFS

Place it next to the existing:

SHARE LEAGUE TABLE

button.

The button must only appear to the league creator.

Do not show it on the public league page.

Opening the button should navigate to a new private route using the existing routing style.

Example concept only:

/leagues/:leagueId/playoffs

Use the project's existing route conventions.

==================================================
SECURITY
==================================================

This page is private.

Only the authenticated league creator may access it.

Every supporting API must:

1. require authentication
2. load the league
3. confirm the authenticated user's ID matches the league owner/creator field
4. return the existing unauthenticated response when logged out
5. return HTTP 403 for an authenticated non-owner

Do not rely only on hiding the Playoffs button.

Direct URL/API access must also be blocked.

Do not expose private membership data publicly.

Use the existing TKO theme.

Reuse existing:
- dark background
- green accent
- cards
- badges
- buttons
- tables
- typography
- spacing
- responsive patterns

Do not create a new design system.

Page title:

PLAYOFFS

Subtitle example:

Review and select players for Champions Night playoff places.

SUMMARY AREA
==================================================

- League name

Use existing league configuration where available.

Do not change qualification rules.

If automatic qualification count is already stored, reuse it.

If it is not stored, do not invent new qualification behaviour just for this page.

Show `—` for unavailable data.

==================================================
FILTERS
==================================================

Add these filters:

1. PLAYER SEARCH
- Search by player name

2. ATTENDANCE
- Minimum attendance slider
- 0% to 100%
- 10% increments

Example:
Minimum attendance: 60%

3. MEMBERSHIP
Options:
- All players
- Members only
- Non-members only

4. QUALIFICATION STATUS
Options:
- All players
- Automatically qualified
- Not automatically qualified

Default on this page should preferably be:

Not automatically qualified

because the page is intended to organise playoff candidates.

Do not alter the actual qualification state.

5. MINIMUM TOURNAMENTS ATTENDED
Options should be generated sensibly from the number of tournaments in the league.

6. TOURNAMENT WINNER
Options:
- All
- Has won a tournament
- Has not won a tournament

==================================================

Provide a Sort By control with:

- League position
- Points: high to low
- Points: low to high
- Attendance: high to low
- Attendance: low to high
- Tournaments attended
- Tournament wins
- Overall 3-dart average
- Best tournament 3-dart average
- First 9 average
- Highest checkout
- Best leg

- Match win %
- Leg win %

Only include sort options for statistics reliably available from Task #103.

Do not invent values.

For "Best leg":
fewer darts is better.

For all percentage and average sorts:
missing values should sort below valid values.

==================================================
TABLE SORTING
==================================================

On desktop, where practical, allow clicking relevant table headings to sort ascending/descending.

Example:

==================================================
PLAYER SELECTION
==================================================

Allow the league creator to manually select players for the playoff field.

Each player row should have:

[ Select ]

or

[ ✓ Selected ]

Selection must NOT automatically qualify the player.

It simply adds them to the organiser's playoff shortlist.

Show a selected-player panel near the top or side of the page.

Example:

PLAYOFF FIELD

4 players selected

- Mark North
- Tom Martin
- Sam Hicks
- Joe Bloggs

Each selected player should have a Remove action.

==================================================
SELECTION PERSISTENCE
==================================================

Persist the playoff selection for that specific league so the creator can leave and return later.

Use the smallest sensible league-scoped database structure.

Do not add fields to global players.

Use the same normalized player identity approach used by Task #103 where appropriate.

Prevent duplicate selected-player records for the same league/player.

Only the league creator may read or modify the selection.
